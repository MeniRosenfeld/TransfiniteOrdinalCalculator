# Development Workflow Guide

This guide explains how to work efficiently with the Transfinite Ordinal Calculator codebase.

---

## 🚀 Quick Reference

### Essential Commands

```bash
npm run dev        # ⚡ Start dev server (USE THIS FOR DEVELOPMENT)
npm run build      # 📦 Build for production (RARE)
npm run preview    # 👀 Preview production build
```

### Development Loop (99% of the time)

```bash
# 1. Start dev server (ONCE)
npm run dev

# 2. Open browser → http://localhost:3000

# 3. Edit files in src/
#    → Changes appear instantly!
#    → No rebuild needed!

# 4. Repeat step 3 all day
```

### Where to Edit

✅ **Edit these:** `src/` directory

```
src/types/           ← Ordinal types
src/operations/      ← Rules and engines
src/conversions/     ← Type conversions
src/*.ts             ← Parser, calculator, UI
```

❌ **Don't edit these:**

```
dist/                ← Generated by npm run build
[root *.js files]    ← Legacy (for compatibility only)
```

### Common Tasks Quick Guide

| Task               | Steps                                                                                                                                                             |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Add feature**    | 1. Edit `src/types/NewFeature.ts`<br>2. Check localhost:3000 (auto-updates!)<br>3. Done!                                                                          |
| **Fix bug**        | 1. Edit `src/operations/BuggyFile.ts`<br>2. Check localhost:3000 (auto-updates!)<br>3. Test fix works<br>4. Done!                                                 |

### Key Principles

1. **Development = `npm run dev`** (fast, instant feedback)
2. **Production = `npm run build`** (rare, before deploy)
3. **Edit `src/` only** (not dist/ or root .js)
4. **Tests via localhost:3000** (during development)
5. **Tests via test files** (before release)

**Remember:** Dev server = instant changes, no rebuild! 🚀

#### Mapping API Notes

- Use the typed mapping APIs: `fTyped` / `fInverseTyped` with `FParams.default(new DoubleContext())` plus the converters in `src/ordinal_mapping/OrdinalMapping.ts`.
- The legacy compatibility module has been removed; update imports accordingly.
- Out-of-range inverse inputs throw the canonical message `Input value <x> is outside the valid range [0,<max>]`.

## Development Modes

### 🚀 Development Mode (RECOMMENDED)

**Use this for daily development - changes appear instantly!**

```bash
npm run dev
```

**What it does:**

- Starts Vite dev server at `http://localhost:3000`
- **Hot reload** - changes to `src/` files appear instantly in browser

**When to use:**

- Before deploying to GitHub Pages
- Testing production bundle
- Measuring bundle size
- Final verification before release

**Test files for production mode:**

- `tests/ordinal_calculator_test.html` - loads `dist/assets/bundle.js`

## Development Server Details

### Vite Dev Server Features

**Hot Module Replacement (HMR):**

- Edit `src/*.js` → changes appear instantly
- Browser state preserved
- No page reload for most changes
- Extremely fast (<100ms)

**Access points:**

```
http://localhost:3000/              # Main calculator (index.html)
http://localhost:3000/src/main.js   # Entry point (for test files)
```

**How it works:**

- Vite serves files directly from `src/`
- Transforms ES6 modules on-the-fly
- No bundling (faster)
- Source maps for debugging

### Production Build vs Dev Server

| Feature         | Dev Server        | Production Build       |
| --------------- | ----------------- | ---------------------- |
| **Speed**       | Instant           | 300-400ms              |
| **Iteration**   | Edit → See change | Edit → Build → Refresh |
| **Bundle**      | No bundling       | Optimized 118KB        |
| **Source Maps** | Always            | Yes                    |
| **Minified**    | No                | Yes                    |
| **File Size**   | Larger            | Smaller                |

## Troubleshooting

### "Changes aren't appearing"

**If using dev server (localhost:3000):**

- Changes should appear instantly
- If not, check terminal for errors
- Try hard refresh: Ctrl+Shift+R

**If using production tests:**

- You need to rebuild: `npm run build`
- Then refresh browser
- This is expected - use dev mode instead!

### "Module not found errors"

- Check that npm run dev is running
- Check file paths in import statements
- Remember to use `.js` extension in imports

### "Tests not running"

**Legacy test files** (`tests/ordinal_enf_test.html`):

- Load from root .js files
- Don't need dev server or build
- Open directly in browser

**New test files** (`tests/*.html`):

- Load from `dist/assets/bundle.js`
- Need `npm run build` first
- Use for production testing only

## Testing System

### Type-checking browser test pages

- Run `npx tsc --noEmit -p tsconfig.tests.json` to type-check all files under `src/tests/**/*`, including the HTML-driven browser suites.
- DOM access in tests should use helpers from `src/tests/testUtils.ts` (e.g., `requireElementById`) instead of raw `document.getElementById` to avoid nullability issues.
- Prefer the shared error helper patterns (`toErrorMessage`, type guards such as `isOrdinal`) used across `simplify_test.ts`, `fInverse_test.ts`, and related suites to keep the test pages type-safe.

### Declarative Test Format

Tests use a declarative format with variable substitution:

```javascript
const tests = [
  {
    name: "Associativity of Addition",
    lhs: "(a+b)+c",
    rhs: "a+(b+c)",
    condition: undefined, // optional precondition
  },
  {
    name: "Multiplication Monotonicity",
    lhs: "a*b ? a*c",
    rhs: "b ? c",
    condition: "a > 0", // only test when a > 0
  },
];

// Variable substitution
const substitutions = new Map([
  ["a", ordinalA],
  ["b", ordinalB],
  ["c", ordinalC],
]);

const results = runTestList(tests, substitutions);
```

### Benefits

- **Concise:** 90% reduction in test code
- **Declarative:** Clear mathematical intent
- **Flexible:** Easy to add new test cases
- **Conditional:** Tests can have preconditions

## Implementation Details

### Type Domains

The codebase maintains clear semantic separation between two numeric domains:

- **BigInt:** Used for integers in ordinal structure
  - Finite ordinal values (e.g., `FiniteOrdinal(42n)`)
  - CNF coefficients
  - Tower heights
  - Any discrete count or index
- **NumericValue\<T\>:** Used for mapped real values
  - Results from `f(α)` mapping ordinals to reals
  - Intermediate calculations in ordinal mapping
  - Interval arithmetic bounds
  - Scale parameters in FParams

**Principle:** Never mix these domains. BigInt represents mathematical integers in ordinal theory; NumericValue represents real numbers in [0,1].

---

## Ordinal Mapping System

The ordinal mapping system provides `f: α → ℝ` bijection between ordinals below ε₀ and real numbers in [0,1].

### Architecture

- **`NumericValue<T>`**: Abstract base for numeric types
- **`DoubleNumericValue`**: Fast IEEE 754 arithmetic (default)
- **`RationalNumericValue`**: Exact BigInt-based rational arithmetic
- **`Interval<T>`**: Interval arithmetic with type safety
- **`NumericContext<T>`**: Factory pattern for creating numeric values
- **`FParams<T>`**: Type-safe parameters with precomputation

### Key Components

```typescript
// Create context
const ctx = new DoubleContext();

// Create parameters
const params = new FParams(
  ctx,
  ctx.fromNumber(3), // hScale (addition)
  ctx.fromNumber(3), // wScale (multiplication)
  ctx.fromNumber(3), // eScale (exponentiation)
  ctx.fromNumber(3), // zScale (tetration)
  ctx.fromNumber(3) // tScale (epsilon numbers)
);

// Forward mapping: ordinal → real
const value = fTyped(ordinalRepresentation, params);

// Inverse mapping: real → ordinal
const interval = new Interval(ctx.fromNumber(0.5), ctx.fromNumber(0.6));
const ordinalRep = fInverseTyped(interval, params);
```

### Design Principles

1. **Generic over numeric type:** Works with doubles, rationals, or custom types
2. **Interval containment:** `fInverse` prefers simpler ordinals when multiple satisfy the interval
3. **Precomputation:** FParams precomputes `f(ωⁿ)` and `f(εₙ)` for efficiency
4. **Memoization:** Global cache improves performance for repeated calculations
